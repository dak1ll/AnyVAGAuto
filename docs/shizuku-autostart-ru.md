# Автозапуск Shizuku / Shevery без root (Android 10–17, включая Xiaomi / HyperOS / MIUI)

Этот документ описывает реальные способы автоматического или максимально быстрого запуска **Shizuku** (или его форка **Shevery**) после перезагрузки телефона **без root-прав**, а также честные системные ограничения Android.

---

## Почему Shizuku сбрасывается после перезагрузки (и почему без Wi-Fi не обойтись)

Приложения в Android работают с правами обычного пользователя и не могут самостоятельно повысить свои привилегии до `shell` (UID `2000`), который нужен `AnyAuto` и `UnknownAuto` для создания виртуального экрана и ввода нажатий.

Без root получить UID `2000` можно только через **ADB**:
- **На Android 11–17** — через встроенную **Беспроводную отладку** (Wireless Debugging), где телефон «подключается» к локальному `adbd` по Wi-Fi.
- **На Android 10 и ниже** беспроводного сопряжения без ПК нет: при каждой перезагрузке Android отключает сетевой `adbd`, поэтому для запуска Shizuku без root требуется компьютер (`adb`) или OTG-подключение к другому устройству.

При любой перезагрузке телефона Android **принудительно выключает Беспроводную отладку** (`adb_wifi_enabled = 0`) и завершает фоновый процесс Shizuku. При этом **само сопряжение (pairing) сохраняется** — вводить 6-значный код заново не нужно, достаточно снова включить Беспроводную отладку при наличии Wi-Fi и нажать «Запуск».

> **Важно:** если на телефоне с **Android 13 или ниже** всё же есть root, в `AnyAuto` всё равно запускайте Shizuku через **Беспроводную отладку**, а не через root: на Android 13 и ниже система не разрешает root-процессу создавать виртуальный экран от имени `shell`.

## Вариант 1: Shevery (рекомендуемый форк Shizuku) или официальный Shizuku

Оба варианта полностью совместимы с `AnyAuto` и `UnknownAuto` (в `AnyAuto` приложение автоматически определяет и официальный Shizuku, и форки вроде Shevery по binder-провайдеру):

- **Официальный Shizuku:** [shizuku.rikka.app](https://shizuku.rikka.app/), [GitHub Releases](https://github.com/RikkaApps/Shizuku/releases/latest), [Google Play](https://play.google.com/store/apps/details?id=moe.shizuku.privileged.api).
- **Shevery (форк Shizuku с акцентом на автозапуск при загрузке):** [GitHub](https://github.com/HmnDev-Tech/shevery) (раздел Releases).

> Не скачивайте APK со сторонних зеркал и форумов — используйте только официальные релизы разработчиков.

### Первичное сопряжение (делается один раз на телефоне без ПК, Android 11+)

1. Включите **Для разработчиков** (`Настройки → О телефоне → 7 раз нажмите на Номер сборки / Версию ОС`).
2. Подключите телефон к **любой сети Wi-Fi** (интернет не обязателен, достаточно самого факта Wi-Fi-соединения).
3. Откройте **Shizuku** (или **Shevery**) и в разделе *Запуск через Беспроводную отладку* нажмите **Сопряжение** (Pairing), разрешив уведомления.
4. Откройте `Для разработчиков → Беспроводная отладка`, включите её, нажмите **Подключить устройство с помощью кода подключения** — не закрывайте окно с 6-значным кодом.
5. Опустите шторку уведомлений и введите 6-значный код в уведомление Shizuku / Shevery.
6. Вернитесь в Shizuku / Shevery и нажмите **Запуск**.
7. **Рекомендация:** в разделе *Для разработчиков* включите **Отключить таймаут авторизации adb** (`Disable adb authorization timeout`), чтобы сопряжение не сбрасывалось через 7 дней без использования.

### Как работает автозапуск в Shevery

- В **Shevery** предусмотрен сценарий автоматического запуска службы после загрузки при наличии Wi-Fi и выданного разрешения `WRITE_SECURE_SETTINGS` (чтобы Shevery мог сам включить настройку `adb_wifi_enabled = 1`).
- **Честное ограничение:** если при загрузке телефон не подключён к Wi-Fi (например, вы перезагрузили смартфон на подземной парковке без сети), Android не поднимет Беспроводную отладку. Как только телефон подключится к Wi-Fi (или к точке доступа), службу можно запустить повторно без ПК.

## Вариант 2: Автоматизация MacroDroid / Tasker после перезагрузки

Если вы используете официальный **Shizuku** (или хотите полностью контролировать момент включения `adb_wifi_enabled`), удобно настроить макрос в **MacroDroid** или профиль в **Tasker**.

### Шаг 1. Однократная выдача `WRITE_SECURE_SETTINGS`

Без этого системного разрешения ни MacroDroid, ни Tasker не смогут программно включить Беспроводную отладку (`adb_wifi_enabled = 1`).

Подключите телефон к ПК по USB с включённой **Отладкой по USB** и выполните одну из команд:

- Для **MacroDroid**:
  ```sh
  adb shell pm grant com.arlosoft.macrodroid android.permission.WRITE_SECURE_SETTINGS
  ```
- Для **Tasker**:
  ```sh
  adb shell pm grant net.dinglisch.android.taskerm android.permission.WRITE_SECURE_SETTINGS
  ```
- Общий шаблон для другого приложения автоматизации:
  ```sh
  adb shell pm grant <package_name> android.permission.WRITE_SECURE_SETTINGS
  ```

> **Подсказка (без ПК, если Shizuku уже запущен):** если вы уже запустили Shizuku вручную или через Shevery, то `pm grant <package_name> android.permission.WRITE_SECURE_SETTINGS` можно выполнить прямо на телефоне через приложение с доступом к Shizuku (например, терминал вроде aShell / Termux с rish).
>
> **Примечание для Xiaomi / HyperOS / MIUI:** перед выполнением `pm grant` обязательно включите в *Для разработчиков* пункт **Отладка по USB (Настройки безопасности)** — иначе MIUI/HyperOS заблокирует `pm grant` ошибкой безопасности.

### Шаг 2. Настройка правила (триггеры и действия)

1. **Триггеры:**
   - `Загрузка устройства` (`Device Boot`) **и/или** `Подключение к Wi-Fi` (`Wi-Fi Connected`).
   - Важно проверять условие **Wi-Fi подключён**: без Wi-Fi Android 11+ не позволяет активировать `adb_wifi_enabled`.
2. **Действия:**
   1. **Пауза 5–10 секунд** (`Wait 5–10s`), чтобы после загрузки успели инициализироваться системные службы и Wi-Fi.
   2. **Записать системную настройку (`Global`)**:
      - Таблица: `Global`
      - Ключ: `adb_wifi_enabled`
      - Значение: `1`
   3. **Запуск службы:**
      - Для **Shevery** — запустить приложение / триггер автозапуска после загрузки.
      - Для официального **Shizuku** — открыть экран Shizuku (в новых версиях Android официальный Shizuku не всегда запускает `adbd`-подключение полностью скрыто без открытия экрана, поэтому для 100% надёжности можно открыть Shizuku и при необходимости нажать кнопку запуска через встроенный жест/UI-клик MacroDroid/Tasker, либо нажать вручную один раз).
   4. **Опционально — восстановление и уведомление:**
      - Через 10–15 секунд после запуска можно вернуть `adb_wifi_enabled = 0`, если не хотите оставлять Беспроводную отладку включённой постоянно (самому уже запущенному процессу Shizuku открытый порт после старта обычно не нужен, но на некоторых прошивках отключение `adb_wifi_enabled` завершает сервис — проверьте на своей прошивке!).
      - Если Wi-Fi при загрузке не обнаружен — вывести уведомление с напоминанием включить точку доступа / Wi-Fi.

### Что делать в машине, если поблизости нет Wi-Fi

Если телефон перезагрузился в дороге и рядом нет домашнего Wi-Fi:
- На 10 секунд раздайте Wi-Fi с другого телефона, мобильного роутера или встроенной точки доступа ГУ автомобиля.
- Запустите Shizuku / Shevery — после того как служба перешла в статус **Работает**, Wi-Fi можно отключить.

> **Честное ограничение:** пока телефон не перезагружался и система не выгрузила процесс Shizuku по нехватке памяти / ограничениям батареи, Shizuku продолжает работать и без Wi-Fi. Самая частая причина «отвала» Shizuku в дороге — не отсутствие Wi-Fi, а агрессивное энергосбережение прошивки.

## Чек-лист Xiaomi / HyperOS / MIUI

На устройствах Xiaomi, Redmi и POCO стандартные ограничения фона и безопасности почти всегда мешают как автозапуску, так и управлению на экране авто. Проверьте все 4 пункта:

1. **Автозапуск:**
   `Настройки → Приложения → Разрешения → Автозапуск` (или *Фоновый автозапуск*) — включите для **AnyAuto**, **Shizuku / Shevery** и приложения автоматизации (**MacroDroid / Tasker**).
2. **Контроль активности (батарея):**
   Откройте свойства каждого из этих приложений → `Контроль активности` → выберите **Без ограничений**.
3. **Закрепление в недавних:**
   Откройте список недавних приложений (Recents), зажмите или потяните карточку приложения (зависит от стиля Recents) и нажмите иконку **Замок** для **AnyAuto** и **Shizuku / Shevery**, чтобы система не выгружала их при очистке памяти.
4. **Настройки для разработчиков:**
   `Настройки → Расширенные настройки → Для разработчиков`:
   - Включите **Отладка по USB**;
   - **Обязательно включите `Отладка по USB (Настройки безопасности)`** (обычно находится сразу под «Отладкой по USB», для включения требует подтверждения с небольшой задержкой и иногда авторизацию Mi-аккаунта). Без этого переключателя HyperOS/MIUI блокирует инъекцию нажатий (`INJECT_EVENTS`) на экране автомобиля и выдачу `WRITE_SECURE_SETTINGS` через ADB. После включения перезапустите Shizuku / Shevery.

## Проверка без ПК перед поездкой

Перед тем как идти в машину и подключаться к Android Auto:

1. Откройте **AnyAuto** на телефоне.
2. Убедитесь, что наверху отображается зелёный статус **`Shizuku работает`** (или **`Shevery работает`**).
3. Убедитесь, что нет карточек предупреждений HyperOS / батареи (если есть — исправьте и перезапустите Shizuku).
4. Нажмите **Попробовать** рядом с нужным приложением, чтобы проверить запуск виртуального экрана и ввод нажатий прямо на телефоне.
5. Убедитесь в меню `⋮ → Установка для автомобиля`, что **AnyAuto** установлен через **UnknownAuto** с меткой Google Play (иначе на реальном автомобиле он не появится в списке Android Auto, хотя режим «Попробовать» и эмулятор DHU будут работать).
